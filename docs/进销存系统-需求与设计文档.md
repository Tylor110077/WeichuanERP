## 1. 项目概述

### 1.1 背景与目标

企业需要一套进销存（进货—售卖—库存）管理系统，核心诉求：

- **一键进货**：登记进货的成本、数量、单位（可自定义单位）、进货来源（供应商）。
- **一键售卖**：向客户开售卖单（售价、客户、数量、单位）；**当库存不足时，开售卖单的同时自动补货并即时入库**（自动生成进货单、按当次设置的进价入库，库存不为负）。
- **企业级安全**：操作员标识（谁在何时做了什么）、角色权限、审计留痕、数据安全。
- **完整业务闭环**：库存、资金往来（应收/应付）、报表。

### 1.2 用户群体

| 角色 | 说明 | 典型人数 |
|---|---|---|
| 管理员 | 系统运营者：用户/商品/基础资料管理、全部权限 | 1 ~ 2 |
| 业务员 | 开进货单、售卖单、处理收货/退货的操作人员 | 2 ~ 20 |
| 老板/财务 | 看全部单据、报表、成本毛利、管理应收应付 | 1 ~ 3 |

### 1.3 术语表

| 术语 | 定义 |
|---|---|
| 商品档案 | 商品主数据（编码、名称、规格、分类、单位、参考价、预警线），开单只能从档案中选择 |
| SKU/商品编码 | 商品唯一编号，系统自动生成 |
| 单位 | 计量单位（米、卷、箱、件、个、吨…），维护在单位字典中，每个商品绑定唯一单位 |
| 进货单 | 向供应商采购的单据，含数量、单位、进价、应付金额 |
| 售卖单 | 向客户销售的单据，含数量、单位、售价、应收金额 |
| 自动补货单 | 售卖单提交时因库存不足自动生成的进货单（状态=已入库，生成即入库） |
| 待收货 | 仅指手动进货单：已生成、实物未到、库存未增加的状态 |
| 已入库 | 库存已增加，成本已按移动加权平均计入 |
| 负库存 | **业务上不允许出现**；库存不足时由自动补货即时入库兜底，防御性标红检测异常 |
| 移动加权平均 | 库存成本计算方法：(原库存金额 + 本次进价×数量) ÷ (原数量 + 本次数量) |
| 成本快照 | 销售时对当次移动加权成本做记录，保证历史毛利不随后续进货变动 |

## 2. 总体业务流程

### 2.1 核心业务场景

```
【进货】业务员开进货单 ──► 供应商送货 ──► 确认入库（库存+、成本重算）
【售卖】业务员开售卖单 ──► 缺货商品自动补货即时入库 ──► 扣库存（保证不为负）──► 提交售卖单
【进货退货】按原进货单开退货单 ──► 库存-、应付冲减（可选部分退货）
【销售退货】按原售卖单开退货单（退货入库）──► 库存+、应收冲减
【收款/付款】针对售卖单收款、针对进货单付款，支持部分收付 → 形成应收应付往来
【报表】库存/进销存汇总/往来/毛利/业绩
```

### 2.2 自动补货机制（本系统关键设计）

**规则**：售卖单提交时，系统在同一个数据库事务内：

1. 逐商品检查库存，**扣减后不允许为负**（评审会已确认：禁止负库存）；
2. 若某商品需求 > 当前库存，按 **缺货数量** 自动生成进货单，状态 = **已入库（生成即入库）**；
3. 自动进货单 **按供应商拆单**（一张售卖单缺多个供应商的货 → 拆成多张进货单）；
4. 进货单元行预填 **该商品最近一次进价**，操作员可在提交售卖单时 **直接修改**（满足"能够设置其进货价格"）；
5. 自动进货单与触发它的售卖单 **双向关联**（进货单上记录 source_sale_order_id，售卖单上可查"自动生成的进货单"），便于追溯；
6. 自动补货入库与销售扣减在同一事务完成：先按进价入库（移动加权、写 purchase_in 流水），后扣减销售（写 sale_out 流水），**库存全程不为负**。

**为什么是"生成即入库"**：评审会确认"不允许负库存、开单不被卡"，要求缺货时当场快速补单入库；代价是货未到时账面先有库存，通过自动补货标记（source_type=auto）与审计留痕追溯账实差异。后续如企业要求严格账实一致，可切换为"先卖后补 + 待收货"模式，数据模型已兼容（status 字段保留 pending）。

### 2.3 单据状态机

```
手动进货单：  待收货(pending) ─► 已入库(received) ─► (作废 voided)
                        │                               ▲
                        └──── 作废(未入库时) ────────────┘
自动补货单：  已入库(received，生成即入库) ─► (作废 voided，库存冲回)
售卖单：      已开单(confirmed) ─► (作废 voided)
退货单：      已开单(confirmed) ─► (作废 voided)
收款/付款单：  已登记(confirmed) ─► (作废 voided，冲回单据收付金额)
```

规则：**所有正式单据不允许"修改"，只能作废重开**。作废为软删除，记录作废人/作废时间/原因，已入库的进货单作废需先将库存冲回（系统自动生成反向库存流水），已确认售卖的作废同理。

## 3. 功能需求

### 3.1 基础资料管理（管理员维护）

- **商品档案**：编码（自动）、名称、规格、分类、单位、参考进价、参考售价、库存预警线、状态（启用/停用）。开单只能从商品档案中选择，不允许手输名称。
- **单位字典**：名称（米、卷、箱、件…），启用/停用，不可删（被引用）。
- **分类**：商品分类（树形，一级即可，可扩展）。
- **供应商**：名称、联系人、电话、地址、备注、状态。
- **客户**：名称、联系人、电话、地址、备注、状态。

### 3.2 进货管理

- 新建进货单：选供应商 → 选商品 → 填数量/单位（默认商品单位）/进价 → 自动算金额，可添加多行。
- 一键进货：给定期望商品与数量，系统按供应商自动拆分并预填最近一次进价。
- 进货单列表：按单据号/供应商/状态/日期筛选；详情页支持**确认入库**（收货）、作废。
- 进货单记录应付款：合计金额、已付金额，可在进货单详情上直接做付款登记。

### 3.3 销售管理（一键售卖）

- 新建售卖单：选客户 → 选商品 → 填数量/单位/售价（预填参考售价，可改）→ 自动算金额，可添加多行。
- **提交时**：若商品库存不足 ↓
  - 界面提示缺货商品清单，显示将自动生成的补货进货单（供应商、数量、预填进价，**进价可改**）；
  - 确认后系统在一个事务内完成：生成补货进货单（已入库，按当次进价即时入库）→ 扣库存（**保证不为负**）→ 提交售卖单；
  - 同单中可混合存在"库存充足直接扣"与"不足自动补货"两种商品。
- 售卖单列表：按单据号/客户/状态/操作员/日期筛选；支持作废（作废时库存冲回）。
- 售卖单记录应收款：合计金额、已收金额，可做收款登记（支持部分收款、挂账）。
- **操作员标识**：单据记录创建人/创建时间；业务员默认只能查看自己开的单（见权限矩阵）。

### 3.4 进货收货入库（手动进货单）

- 对状态=待收货的**手动进货单**执行"确认入库"：事务内库存 += 数量、按移动加权平均重算成本、写库存流水、单据状态 → 已入库。未入库前的成本价可改（供应商报价调整场景）；入库后不可改。
- 自动补货单在售卖单提交时已即时入库，不经过本流程。

### 3.5 退货管理

- **进货退货**：关联原进货单，选商品与退货数量（≤ 原单数量 − 已退数量）、退货价，确认后库存 −、应付冲减。支持部分退货、多供应商单依次退。
- **销售退货**：关联原售卖单，选商品与退货数量、退货价，确认后库存 +、应收冲减。期初库存校验：退货入库按出库时的成本快照回补成本。

### 3.6 库存管理

- 全局单一库存（不分仓库；表结构预留 warehouse_id，二期扩展多仓库/调拨/盘点）。
- 库存查询：商品、当前库存数量、成本金额（单价×数量）、最近进价、预警状态；**异常负库存标红（防御性检测，正常业务不会出现）**；低于预警线的商品在"预警列表"单独展示。
- 库存流水：每笔库存变动（进货入库/销售出库/进货退货/销售退货/作废冲回）记录：变动前后数量、单价、成本、操作人、来源单据号，可追溯。

### 3.7 应收应付与收付款

- 应收：按客户汇总未收金额；应付：按供应商汇总未付金额。
- 收款登记/付款登记：选择单据、金额、方式（现金/银行转账/微信/支付宝）、备注、操作人；支持部分收付、多次登记。
- 往来明细：客户/供应商 × 单据 × 收付记录，用于对账。

### 3.8 报表中心（一期 6 张）

| 报表 | 内容 | 导出 |
|---|---|---|
| 库存查询 | 数量、成本金额、最近进价、预警状态 | Excel |
| 进销存汇总 | 按期间：采购额、销售额、毛利润（销售额 − 成本快照） | Excel |
| 应付明细 | 供应商、单据、应付、已付、未付 | Excel |
| 应收明细 | 客户、单据、应收、已收、未收 | Excel |
| 单品销售排行 | 单品销量、销售额、毛利，按期间 | Excel |
| 操作员业绩 | 按操作员：开单数、销售额、毛利 | Excel |

### 3.9 用户与权限

- 账号 + 密码登录；密码 argon2/bcrypt 哈希存储；连续 5 次失败锁定 15 分钟；管理员可重置密码、停用用户。
- 固定三档角色（预留扩展）：管理员 / 业务员 / 老板·财务，详见第 5 章权限矩阵。
- 前端仅做展示控制，**后端每个接口必须鉴权**（服务端为准）。

### 3.10 审计日志

- 审计表记录关键动作：登录、开单、入库、作废、修改档案、改价、删除等。
- 每条记录：操作人、时间、来源 IP、动作类型、对象类型与编号、**变更前后值（JSON 快照）**。
- 审计日志仅管理员可查看，且不允许删除/修改。

## 6. 数据模型设计

### 6.1 实体关系（概念）

```
users 1─N purchase_orders / sale_orders / returns / payments（操作人）
products N─1 units、N─1 product_categories
suppliers 1─N purchase_orders / purchase_returns
customers 1─N sale_orders / sale_returns
purchase_orders 1─N purchase_order_items；source_sale_order_id ─► sale_orders
sale_orders 1─N sale_order_items

```

## 7. 关键业务规则

### 7.1 售卖开单事务（含自动补货）

单个数据库事务内按顺序执行：

1. 校验权限、客户/商品有效性（商品须启用）；
2. 逐行检查缺货（需求 > 当前库存），缺货行按缺货数量聚合到供应商 → 生成进货单（status=received、source_type=auto、source_sale_order_id=本单），价格 = 用户在开单界面设置值（默认最近进价）；并按移动加权平均即时入库：stock_qty += 缺货量、写 stock_movements（purchase_in，before/after 快照）；
3. 逐行扣减 products.stock_qty（**扣减后保证 ≥ 0**，即不允许负库存）；写 stock_movements（sale_out，before/after 快照）；按当前 avg_cost 写入 cost_amount 快照；
4. 提交售卖单主表与明细、生成单据号；写审计日志。

任一步失败则整体回滚，保证库存、单据、流水三者永远一致。

### 7.2 进货入库事务（移动加权平均）

1. 校验单据状态 = pending（仅手动进货单；自动补货单在售卖事务内已直接入库）；
2. 正常场景库存非负：新成本 = (stock_amount + quantity × 进价) ÷ 新总量，更新 stock_qty / stock_amount / avg_cost；
3. 防御性分支（理论不会触发，保留以兼容历史数据）：新总量 ≤ 0 时按"冲负库存优先"分段——先以原成本回补负数部分，剩余部分按新进价计入新成本（见 docs/细节评审.md B3 数值示例）；
4. 写 stock_movements（purchase_in）；状态 → received；写审计。

### 7.3 单据编号规则

`前缀 + 时间 + 4 位序号`：进货 PO + yyyyMMdd + 0001；售卖 SO；进货退货 PRF；销售退货 PRS；收款/付款 PAY/POF。序号按日自增，唯一索引防并发重号。

### 7.4 作废与退货

- 作废：软删除，记录操作人/时间/理由；已影响库存的单据作废时自动生成反向库存流水（void_reverse），并冲回应收/应付。
- 退货使用独立退货单关联原单，数量累计不得超过原单可退数量；退货不动原单数据。
- 销售退货入库按原 sale_order_items.cost_amount 快照回补库存成本，保证毛利口径正确。

### 7.5 权限与审计原则

- 所有写操作：后端服务端鉴权（非前端隐藏）；单据操作人 = 当前登录用户，不可伪造。
- 所有关键动作写 audit_logs（含变更前后值）；审计日志不可修改、不可删除（数据库层面也限制）。
- 涉及金额/成本的数据（成本价、毛利）默认对业务员禁用显示，前端与后端接口双重屏蔽。

## 8. 非功能需求

### 8.1 安全性

| 项 | 方案 |
|---|---|
| 认证 | 账号+密码（argon2 哈希、每用户独立盐）；连续 5 次失败锁定 15 分钟；管理员可重置/停用 |
| 会话 | HttpOnly + Secure + SameSite Cookie；会话有效期可配（默认 8 小时，超时重登）；登出即失效 |
| 传输 | 全站 HTTPS（强制 HSTS）；生产环境验证证书 |
| 注入防护 | 全部走 ORM 参数化查询（Prisma），禁止拼接 SQL |
| CSRF / XSS | 表单 CSRF Token；服务端对用户输入统一校验/转义；富文本不开放 |
| 数据库 | 独立数据库账号、最小权限；定期备份；生产环境不开放公网数据库端口 |
| 审计 | 见 7.5；登录成功/失败均记录 login_logs |
| 数据归属 | 数据保存在企业自己的服务器，不经过第三方服务 |

### 8.2 性能

- 数据规模设计目标：商品 ≤ 5,000，单据 ≤ 10 万/年，并发 ≤ 20 人；MySQL 8 单机足够。
- 库存变动与单据写入必须在单事务内完成；products.stock_qty 冗余但以流水为最终依据，定期对账脚本校验。
- 列表页分页（每页 20），查询字段建索引（order_no、supplier_id、customer_id、created_at、operator_id）。

### 8.3 备份与容灾

- MySQL 每日全量备份（自动任务），保留 30 天；异地留存（云对象存储或与本机分离的磁盘）。
- 上线前演练一次"全库恢复"流程。
- 应用日志与审计日志独立保留（审计日志建议 ≥ 2 年）。

### 8.4 部署

- 单台云服务器（腾讯云/阿里云 2C4G 起）+ Docker：应用容器 + MySQL 容器（或独立 MySQL）。
- 反向代理（Nginx）+ HTTPS 证书自动续签；服务器仅开放 80/443。
- 域名访问，企业内部可加 IP 白名单/内网访问。
