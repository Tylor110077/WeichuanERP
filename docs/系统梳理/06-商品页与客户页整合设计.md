# 06 · 商品页与客户页的整合设计

> 需求：`/products` 与 `/customers` 现在是"一叠横向长条"（筛选条 + 3 个折叠管理区 + 列表），
> 视觉上很碎、主内容被挤到下面。要求**各自**把这些功能整合成更优雅的形态——
> 不是把商品页和客户页合并，而是每个页面内部重新组织。

## 一、问题诊断（实测）

| 页面 | 现状纵向结构 | 问题 |
|---|---|---|
| `/products`（365 行） | 标题行 → 厂家筛选条 → 折叠：厂家管理 → 折叠：分类管理 → 折叠：单位管理 → 商品列表 | 3 条折叠长条抢占首屏；分类/单位在真实数据里各只有 1 条，却各占一整条；商品列表被推到折叠线以下 |
| `/customers`（629 行） | 标题行 → 搜索条 → 组织/标签筛选条 → 折叠：组织管理 → 折叠：标签管理 → 折叠：客户画像 → 客户列表 | 4 条横向栏；客户画像（信息量大）藏在折叠里；客户列表同样被压到下面 |

共同病症：**把"维护类功能"和"查看类功能"平铺在同一层**，于是页面变成一排排长条，每一条都只用到页面宽度的一小部分。

## 二、设计原则（沿用本项目既有风格）

1. **一条横向栏解决切换，而不是多条横向栏堆叠**：用页面级页签（tab）把"查看"和"维护"分成几个互斥的工作区。
2. **沿用已有模式**：报表中心已经在用「链接式页签 + `?tab=` 参数」；应收应付用「分段控件」切换视图。两者都是服务端渲染、可分享、可回退，不引入新交互范式。
3. **默认落在最高频的工作区**：商品页默认「商品」、客户页默认「客户」——打开就能干活，维护类功能按需切换。
4. **每类资料维护时占满宽度**：现在挤在折叠条里，切到页签后表单与表格能用满整行，编辑体验更好。
5. **不改业务规则、不改数据库、不减少功能**：原来能做到的每件事都还在，只是换了位置（旧地址 `?tab=xxx` 明确可分享）。
6. **页签带数量**：`商品 2` / `厂家 2` / `分类与单位 1 · 1`，一眼知道每块有什么，避免"点进去才发现是空的"。

## 三、目标结构

### `/products`

```
商品与厂家                                    [+ 新建商品]
[ 商品 2 ] [ 厂家 2 ] [ 分类与单位 1 · 1 ]          ← 一条页签
────────────────────────────────────────────────
商品页签：
  工具栏：厂家筛选 chips（全部 / 各厂家 / 未填厂家）＋ 搜索框（名称/编码/厂家）
  商品列表（编码 名称 厂家 分类 单位 参考进价 库存 预警线 状态 操作）
厂家页签：
  厂家管理（含"供应商品"数、行内编辑、停用/删除）
分类与单位页签：
  两栏并排：商品分类管理 ｜ 单位字典管理
```

### `/customers`

```
客户管理                                      [+ 新建客户]
[ 客户 2 ] [ 组织与标签 1 · 1 ] [ 客户画像 1 ]       ← 一条页签
────────────────────────────────────────────────
客户页签：
  工具栏：组织/标签筛选 ＋ 关键词搜索（名称/联系人/电话）
  客户列表（名称 联系人 电话 组织 标签 状态 操作）
组织与标签页签：
  两栏并排：客户组织管理 ｜ 客户标签管理
客户画像页签：
  期间快捷 + 起止日期 + 客户画像表（单数/销售额/毛利/平均利润率 → 看明细）
```

**为什么"分类与单位""组织与标签"要两栏并排**：它们各自字段很少（通常只有名称 + 状态），并排后一条横向栏就能容纳两块内容，桌面端不再浪费纵向空间；窄屏自动回落成单列。

## 四、实现要点

- 新增 `src/components/page-tabs.tsx`：`<PageTabs tabs={[{key,label,count,href}]} current />`，
  服务端组件（链接式，无 JS），激活态用 `segActive`、未激活用 `segIdle`，带 `aria-current="page"`。
- 两个页面各自读取 `searchParams.tab`，白名单校验（非法值回落到默认页签，参考报表中心的写法）。
- 页签链接**保留当前筛选**（产品的厂家筛选、客户的搜索与组织/标签、画像的期间），切换页签不丢条件。
- 折叠区（`<details>`）改为页签内容后，原先的「点击展开/收起」提示文案删除；空状态、权限（admin 才能维护主数据）与原来一致。
- 页签内容的容器沿用 `rounded-xl border border-gray-200 bg-white`，与全站卡片一致。

## 五、验收

1. `/products`、`/customers` 首屏只剩「标题行 + 页签行 + 一个工作区」——横向长条从 4~5 条降到 2 条。
2. 三个页签分别可直达：`/products?tab=manufacturers`、`/customers?tab=tags`、`/customers?tab=profile`。
3. 切换页签保留筛选；非法 `tab` 值回落到默认页签且不报错。
4. 窄屏（375px）下单列排布、无横向溢出。
5. `npm test`、`tsc`、`eslint` 全绿；两个页面 200 无报错；商品/客户的增删改功能与原来一致（含 admin 权限控制）。

## 六、与既有设计的关系

- 页签 = 报表中心「页签」模式 + 应收应付「分段控件」令牌，不新造控件。
- 按钮、卡片、空状态、行级二次确认（`RowAction`）、写操作反馈（`FormAlert`）全部沿用第一轮已统一的实现。
- 页面不再堆叠折叠条后，`docs/系统梳理/03-库存与商品.md` 的 P5（商品页拆分）与 `05-客户与系统.md` 的 C6（画像二选一）在本方案里**部分落地**：维护类功能有了清晰归属（页签），画像也回到了客户域内且与列表并列，不再是"折叠在下面的一张表"。
