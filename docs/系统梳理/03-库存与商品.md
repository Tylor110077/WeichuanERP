# 03 · 库存与商品主数据

范围：库存查询（含批次台账）、库存流水、商品与厂家（含厂家/分类/单位管理）、商品建档与编辑。
一句话结论：**"查一个货"这件事被拆到三个互不相连的页面；而"建一个货"要求用户回答 6 个问题，其中 3 个在真实数据里从来没被填过（规格、参考售价、预警线全是空的或默认值）。**

---

## 一、逐页逻辑地图

### 1. 库存查询 + 批次台账 `/inventory`（297 行）

- **唯一职责**：按商品看"现在有多少、值多少钱、最近进价、是否要补货"，并可下钻到某个商品的进货批次。
- **筛选**：`q`（名称/编码）、`warnOnly=1`（只看预警）。
- **主表列**（`inventory/page.tsx:128-140`）：编码 / 名称 / 分类 / 单位 / **库存数量** / 成本金额 / 均价 / 最近进价 / 预警线 / 批次链接 / 状态。
  - 「均价」= 移动加权成本 `avgCost`（4 位小数）；
  - 「最近进价」= 最近一次非作废进货流水 `stockMovement.unitCost`（按 `createdAt desc` 取第一条，`page.tsx:37-48`）——**注意这与「均价」和「批次进价」是三个不同口径**；
  - 负数库存标红（`negative`），预警行整行浅橙底（`warning`）。
- **批次台账**（`batch` 参数，同页下方展开）：进货日期 / 单号 / 厂家 / 来源 / 数量（含"客户 X + 备货 Y"拆分）/ 进价 / 金额，表尾给出**累计进货、进货加权均价**，再单独一行给出**当前库存 / 库存成本 / 移动加权均价**，并附口径说明。批次链接保留 `q`/`warnOnly`，但**不跨到别的页面**。
- **写操作**：无（纯查询）。库存变动只由进货入库、销售出库、退货、作废冲回产生。
- **边界**：无商品时 `EmptyState`+「去建立商品」；批次为空时（本轮修过的文案）提示"该商品还没有进货批次"+ 去开进货单。

### 2. 库存流水 `/stock-movements`（217 行）

- **唯一职责**：按时间列出每一笔库存变动（谁、什么时候、哪张单、变了多少、单位成本）。
- **筛选**：商品（搜索选择器）、业务类型、起止日期；分页保留全部筛选。
- **业务类型 5 类**（`BIZ_TYPE_LABELS`，`stock-movements/page.tsx:20-26`）：进货入库 / 销售出库 / 进货退货 / 销售退货 / 作废冲回。
- **行内**：业务单号已可点进对应单据（本轮新增，`purchase_in`→进货单、`sale_out`→售卖单；退货/作废仍为纯文本）。
- **权限**：`sales` 角色不可见（`NoPermission`）。

### 3. 商品与厂家 `/products`（365 行，一页 4 件事）

1. **厂家标签筛选行**：`全部` + 每个厂家（含数量）+ `未填厂家`，点选后标题变成"{厂家} 供应的商品"，可清除筛选。
2. **厂家管理折叠区**：`MasterDataManager`（列：厂家名 / 供应商品数 / 状态 / 操作）——这就是"厂家档案"，已从导航中移除独立页面。
3. **商品分类管理折叠区**、**商品单位管理折叠区**：同样用 `MasterDataManager`。
4. **商品列表**：编码 / 名称（旁挂厂家标签）/ 规格 / 分类 / 单位 / 参考进价 / 参考售价 / 库存 / 预警线 / 状态 / 操作（编辑 → 跳独立页，停用，删除）。

- 首屏渲染 **83 个 `<input>` / 16 个 `<form>`**：三个折叠区的表单 + 商品列表每行 2 个提交表单（停用、删除，见第四节）。

### 4. 商品建档 / 编辑 `/products/new`、`/products/[id]`（57 / 91 行）

用公共 `EntityForm` 渲染 6 个字段（`products/new/page.tsx:38-48`）：

| 字段 | 必填 | 真实数据情况 |
|---|---|---|
| 商品名称（完整名称，含规格） | ✓ | 实际就是型号本身，如 `YJV 3*2.5` |
| 厂家（可搜索，可当场新建） | ✓ | 都填了（华旗 / 金牛） |
| 单位（可搜索） | ✓ | 只有 1 个：米 |
| 分类（可搜索，可不选） | — | 只有 1 个：电线 |
| 参考进价 | —（但服务端按 0 处理） | 填了（99 / 100） |
| 库存预警线（默认 1） | — | **全部是默认值 1** |
| 规格 spec | —（编辑页与名称合一） | **全部为空，从未使用** |
| 参考售价 | — | **全部为 0，从未使用** |

### 5. 厂家档案（`suppliers/actions.ts`）

- 厂家既是"档案"（名称/联系人/电话/地址/备注）又是"补货来源"（开单缺货时按商品上的 `manufacturer` 名称匹配厂家档案，自动补货，找不到就按名称建档）。
- 独立页面（`/suppliers`）已改为 `redirect("/products")`；`/suppliers/new`、`/suppliers/[id]` 仍存在但**零入口**。

### 6. 成本口径（`src/lib/stock-cost.ts`）

`applyStockChange` 实现移动加权平均，含"冲负分段"与"恰好清零时金额归零"的防御分支（有 7 个单元测试覆盖，`tests/stock-cost.test.ts`）。这是全系统最不能动的部分，任何界面改动都不得触及。

## 二、概念与数据的一致性

| 界面叫法 | 数据库字段 | 说明 |
|---|---|---|
| 商品名称（含规格） | `Product.name` | 用户实际把型号写在这里，如 `YJV 3*2.5` |
| 规格 | `Product.spec` | **表单上已与名称合一，字段实际上废弃但列表仍有一列** |
| 厂家 | `Product.manufacturer`（字符串）+ `Supplier.name` | 靠**名称相等**关联，不是一个外键 |
| 单位 / 分类 | `Product.unitId` / `Product.categoryId` | 真实外键 |
| 库存 / 成本金额 / 均价 | `stockQty` / `stockAmount` / `avgCost` | 移动加权 |
| 最近进价 | 由 `stockMovement` 反查 | 与「均价」不同源 |
| 预警线 | `Product.minStock`（默认 1） | 实际等价于"库存为 0 就提醒" |

**必须指出的三处一致性问题**：

1. **「型号」在界面上到处出现，但数据里没有这个东西。** 开单页的商品搜索占位符写着"名称 / 型号 / 厂家 / 编码"（`new-sale-form.tsx:970`），搜索逻辑也把 `spec` 算进匹配范围（`new-sale-form.tsx:315-317`）——但真实数据里 `spec` **恒为 null**（型号其实写在名称里，如 `YJV 3*2.5`）。也就是说：实现没有撒谎，只是这个字段从来没人填；用户按"型号"搜，搜到的其实是名称，容易误判成"系统搜不到"。
2. **厂商/厂家/生产厂家三种叫法**：建档表单叫"厂家"，搜索占位符叫"厂商"，商品列表旁的标签叫"厂家"，`Product.manufacturer` 注释写"厂商"。（本轮已统一界面文案为"厂家"，但占位符里的"厂商"仍混在其中，建议一并改成"厂家"。）
3. **三个"价"口径不同却并排出现**：库存页同时展示「均价」（移动加权）、「最近进价」（最近一笔进货单价）、批次台账里的「批次进价」与「进货加权均价」，以及商品的「参考进价」。没有一处把它们的关系说清楚（只有批次台账下方有一段说明）。
4. **厂家用名称字符串关联**：改名一个厂家档案，历史商品上的 `manufacturer` 不会跟着变，自动补货就会匹配不上（会按新名称再建一个厂家档案）。这是数据层隐患，改动前建议先加一条"厂家改名时同步商品"的逻辑或至少给出提示。

## 三、操作摩擦点

1. **查一个货要跨三页、搜三次商品**（`00-总览` 第三节，T3）：库存查询 → 库存流水 → 价格分析，三页都支持 `productId`，却没有一个链接带过去。
2. **建一个商品要回答 6 个问题，其中 3 个是"系统本可以推断或干脆不问"的**：单位（试运行里只有"米"）、分类（只有"电线"）、预警线（从来没改过默认值）。对电线贸易来说，"单位"几乎总是米，"预警线"几乎总是缺货提醒。
3. **预警的概念在两个页面用两套说法**：商品建档叫"库存预警线（默认 1）"，库存查询的筛选叫"只看预警"（`warnOnly`），而实际语义是"库存为 0 / 已缺货"。
4. **主数据的行级危险操作没有二次确认**：`master-data-manager.tsx:116-141` 里，每行的「停用」和「删除」是直接提交的表单（删除有服务端引用校验，停用没有）；同时**每行渲染 2 个 `<form>` + 2 个隐藏域**，商品/客户等列表因此有 60+ 个表单挤在一个页面里。误点"停用"的后果是：这个商品在开单页搜不到（但不报错说明原因）。
5. **商品列表的"编辑"会跳到独立页面**，而它旁边的厂家/分类/单位管理却是就地编辑——同一页里两套编辑范式。
6. **`/products/new` 与开单页的内联"新建商品"是两套实现**（字段不同、校验不同），长期必然产生"为什么这里能建、那里建不了"的困惑。

## 四、合并 / 重组 / 升级建议

| # | 建议 | 依据 | 影响 | 量 | 风险 |
|---|---|---|---|---|---|
| P1 | **商品维度串起来**：库存查询行加「流水」「价格趋势」两个链接（带上 `productId`）；库存流水与价格分析页顶加"返回库存"；批次台账行加「看该商品的流水」 | 信息气味 + 就近原则；T3 从 3 次搜索变 1 次 | inventory / stock-movements / price-analysis | S | 低 |
| P2 | **建档表单渐进披露**：必填只留"名称 + 厂家"；「单位」默认记住上次选择（或默认"米"）；「分类」「参考进价」「预警线」收进"更多设置"折叠；删除已废弃的"规格"字段展示 | 渐进披露 + 默认值即答案；T5 的必填项从 4 降到 2 | `products/new`、`products/[id]`、`products/actions.ts` | M | 低（字段仍在，只是默认与呈现变化） |
| P3 | **统一"型号"说法**：要么把 `spec` 真正用起来（"型号/规格"独立字段，名称不含型号），要么从所有搜索占位符里删掉"型号"二字 | 术语与字段一致，避免用户找不存在的字段 | 开单页、进货开单、商品列表、搜索选择器 | S | 低 |
| P4 | **主数据行级操作加二次确认**：停用与删除都弹确认（删除已有服务端兜底）；并把每行的 2 个表单合成 1 个（一个表单带 `action` 值区分） | 防错优于报错；同时把 `/products` 的 60+ 表单降到十几个 | `master-data-manager.tsx`、`customer-manager.tsx` | M | 低 |
| P5 | **商品页拆分**：主区只留"商品列表（含厂家筛选）"；厂家/分类/单位的维护移到「基础资料」下的设置页，或在列表里提供"就地新建厂家/分类/单位"的搜索选择器（开单页已有这个模式，可复用） | 一页一件事；分类/单位在真实数据里各只有 1 条，不值得占首页面积 | `products/page.tsx`、新增设置页 | M | 中（要保证"缺货自动补货"仍能找到厂家） |
| P6 | **厂家改名同步商品**：`saveSupplierAction` 改名时，同事务里把 `manufacturer` 等于旧名的商品一起更新，并写审计；或至少在改名时提示影响面 | 单一数据源，避免自动补货失配 | `suppliers/actions.ts` | S | 中（涉及批量更新，要写测试） |
| P7 | **"预警"改说"缺货"**：库存筛选名改为"只看已缺货"，商品建档的预警线说明改为"低于此数量提醒补货（默认 1＝卖完就提醒）" | 用业务语言而非系统语言 | inventory、products | S | 低 |
| P8 | **删除孤儿路由**：`/categories`、`/units`、`/suppliers/new`、`/suppliers/[id]` 改为 `redirect` 到合并后的位置（功能已在商品页原地可用） | 死路由只增加维护面与"两个入口两种行为"的困惑 | 4 条路由 | S | 低 |

## 五、这个模块最该先做的 3 件事

1. **P1 三页互链**（半天，日常查询效率提升最直接，风险最低）。
2. **P2 建档减负**（1 天，直接减少"多建一个商品"的心理成本，而商品档案质量决定后面一切）。
3. **P4 行级操作防错 + 减少表单**（1 天，既防误停用，又让商品/客户这两个最重的页面轻下来）。
