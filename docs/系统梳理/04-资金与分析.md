# 04 · 资金与分析

范围：工作台、应收应付、厂家对账、客户画像、销售分析、价格分析、报表中心（含导出）。
一句话结论：**"销售额 / 成本 / 毛利"这套算法在 5 个页面各写了一遍（口径恰好一致，这是运气好）；但"未收总额"存在真正的口径冲突——工作台算全部时间，应收应付页只算本月、且最多 200 张单**。这是本次梳理发现的唯一一个"数字会算错"的问题，建议优先修。

---

## 一、逐页逻辑地图

### 1. 工作台 `/dashboard`（239 行）

- **唯一职责**：给老板/业务员一个每天第一眼看的总览 + 两个开单快捷入口。
- **4 张数据卡**（`dashboard/page.tsx:69-95`）：今日销售额（今日非作废售卖单金额合计）、今日利润（今日销售额 − 今日成本快照，仅 admin/boss 可见）、应收总额、应付总额。每卡可点击跳转（应收/应付跳 `/receivables-payables?view=...`）。
- **2 个快捷入口卡**：销售开单、进货开单。
- **口径来源**：今日销售额/利润用 Prisma 聚合；应收/应付合计用 `$queryRaw` 全量 SQL 聚合（`page.tsx:34-41`），注释明确写"与应收应付页同口径（单额 − 已收付 − 未作废退货冲减）"——**但实际上与应收应付页的口径并不相同**（见第二节）。

### 2. 应收应付 `/receivables-payables`（308 行）

- **唯一职责**：一个视图（应收/应付切换）+ 顶部筛选 + 未结清单据表 + 合计。
- **筛选**：起止日期（默认 `dateRange()` 未给日期 → **本月 1 号至今**）、对象（客户/厂家，可搜索）、视图切换。
- **表列**：日期 / 单号 / 客户(厂家) / 应收(应付) / 已收(已付) / 退货冲减 / 未收(未付) / 操作（详情 + 登记，登记带 `#receipt`/`#payment` 锚点直达）。
- **合计**：表格下方一行「客户应收合计（未收）」大字 + 说明"当前筛选条件下共多少未结清"。**它只累加查询返回的 ≤200 张单**（`page.tsx:47,56,62`）。
- **写操作**：本页无（收付款登记在单据详情页的区块里；本页只提供跳转与「撤销收款」入口）。
- **权限**：sales 不可见。

### 3. 厂家对账 `/supplier-statement`（219 行）

- **唯一职责**：按厂家 + 期间 + 收付状态，逐单展示进货明细与付款记录（可展开）。
- 与应收应付的差别：它是"按厂家逐单对账"（含已结清单据），应收应付是"只看未结清"。
- **零入口**：全站没有任何链接指向它（`00-总览` 第一节），用户只能手输 URL。

### 4. 客户画像 `/customer-profile`（241 行）

- 按客户 + 期间统计单数/销售额/成本/毛利/平均利润率，选中客户后列出其每张售卖单并可展开明细。
- 入口：客户列表 → 画像表 →「看明细」（唯一的 1 处链接），且客户列表页里**已经内嵌了同一张画像表**（`customers/page.tsx` 第三个折叠区）。
- 自带一份 `dateRange()` 实现（`src/lib/customer-profile.ts:78`）——与 `src/lib/reports.ts:26` 的那份功能相同，属重复实现。

### 5. 销售分析 `/sales-analysis`（234 行）

- 期间快捷（今日/本周/本月/今年/全部）+ 自定义日期；顶部 4 个汇总卡（销售额/成本/总利润/总利润率）。
- 两张表：按商品（销量/销售额/成本/利润/利润率/占比）、按日（单数/销售额/成本/利润）。
- 口径：`销售 = Σ saleOrder.totalAmount`（非作废、期间内）、`成本 = Σ saleOrderItem.costAmount`（成本快照）、`毛利 = 差`。

### 6. 价格分析 `/price-analysis`（323 行 + `lib/price-analysis.ts` 267 行）

- 按商品看"每笔实际售价（灰点）+ 每笔进价（橙点）"，并有每日最高/最低进价连成的着色区间；下方按客户汇总与明细表。
- 口径注释写得很清楚：`单位成本 = 单行 costAmount / 数量（与销售分析、报表中心一致）`（`price-analysis.ts:5`）。
- 默认不选商品时只显示提示，需要用户选商品（`page.tsx:40`）。

### 7. 报表中心 `/reports`（123 行 + `lib/reports.ts` 307 行）

- 6 个页签 + 导出 Excel：库存查询、进销存汇总、应付明细、应收明细、单品销售排行、操作员业绩。
- **其中 4 个页签是其它页面已有的内容**：库存查询 = `/inventory`；应付/应收明细 = `/receivables-payables` + `/supplier-statement`；单品销售排行 = `/sales-analysis` 的按商品表 + `/price-analysis` 的按商品表。
- 独有价值：**进销存汇总**（期间采购额/销售额/成本/毛利）与**操作员业绩**，以及"导出为 Excel"。

## 二、指标口径对照表（重点）

| 指标 | 出现位置 | 定义 | 一致性 |
|---|---|---|---|
| 销售额 | 工作台（今日）、销售分析、价格分析、客户画像、报表中心（汇总/排行） | `Σ saleOrder.totalAmount`，排除 `voided` | ✅ 一致（工作台限今日，其余按期间） |
| 成本（销售成本） | 同上 5 处 | `Σ saleOrderItem.costAmount`（销售时的成本快照） | ✅ 一致 |
| 毛利 / 毛利率 | 同上 5 处 + 价格分析 | 销售额 − 成本快照；毛利率 = 毛利/销售额 | ✅ 一致 |
| 退货冲减 | 应收应付、报表中心（应收/应付明细）、工作台（SQL） | `Σ saleReturn.totalAmount where status='confirmed'` | ✅ 一致 |
| **未收 / 未付合计** | 工作台「应收总额」 / 应收应付页「合计」 | 工作台：`Σ(总额 − 已收 − 退货冲减)` over **全部**单据；应收应付页：同公式但 **仅本月 + 最多 200 张** | ❌ **不一致（同名不同数）** |
| 库存金额 / 均价 | 库存查询、报表中心（库存查询）、进销存汇总 | `Σ product.stockAmount`、`avgCost` | ✅ 一致 |
| 最近进价 | 库存查询、报表中心（库存查询） | 最近一笔非作废 `purchase_in` 流水的 `unitCost` | ✅ 一致（但与"均价"不同口径，界面上没说明） |

### 需要修的一个真问题（数据正确性）

`receivables-payables/page.tsx:47,56` 用 `take: 200` 取单据后在 JS 里求和，且表格**没有分页、也没有"只显示前 200 张"的提示**。而 `dashboard/page.tsx:34-41` 用 SQL 聚合全部单据。后果：

- 单据超过 200 张后，**应收应付页的「合计」会静默少算**，而工作台的数字是对的 → 两个页面显示不同的"未收总额"，用户无从判断哪个可信；
- 应收应付页默认只统计本月（`dateRange()` 未给日期时的默认区间是"本月 1 号 → 今天"，`reports.ts:26-37`），而工作台是全量 → 即便单据不足 200 张，两个数字本来就不同，但界面上**没有任何文字说明这两个"应收总额"的含义不同**。

**建议**：应收应付页的合计改为 SQL 聚合（或至少把 `take` 换成不带上限的聚合查询 + 表格单独分页），并在两处都标明口径文案：工作台卡写"截至今天的全部未收"，应收应付页写"当前筛选条件（默认本月）内的未结清合计"。

## 四、摩擦点（按真实场景）

1. **月末对账**："这个月还差多少钱没收回？"——工作台与应收应付页给的两个数不一样（第二节），且应收应付页默认只算本月、还可能有 200 张上限。
2. **催款**：应收应付页按对方合计只有一行小字（`byCounter`），要点开每条单看；没有"生成催款清单"的出口（导出 Excel 在报表中心，需要另开页面、另选一次期间）。
3. **看"这个月赚了多少"**：工作台只有"今日利润"，想看本月要去「财务 → 销售分析」再选时间范围——而"财务"这个分组名不太会让人联想到"看利润"（`00-总览` 第四节）。
4. **查某货的价格走势**：从库存查过去要重新搜商品（`00-总览` 第三节 T3）。
5. **客户历史**：客户列表内嵌画像表（有毛利），点「看明细」又到另一个页面看到几乎同样的表——多一步，且两处口径若日后改动容易分叉。
6. **厂家对账**：功能存在但完全没人能找到（零入口）。

## 六、这个模块最该先做的 3 件事

1. **F1 修口径**（先确认业务预期：默认该看本月还是全部；确认后 1 天可完成）。
2. **F4 工作台承载"本月"**（1 天，老板每天都会用到，且不涉及新页面）。
3. **F5 + F8 链接补全**（半天，把已经写好但没人找得到的功能接上）。
