# 部署指南（生产）

> 依据《需求与设计文档》8.3 / 8.4：单台云服务器（2C4G 起）+ Docker + Nginx + HTTPS。
> 本文档按"全新服务器"顺序编写；服务器资源与域名待用户提供（文档 11 待办 #8）。

## 1. 服务器准备（一次性）

```bash
# 以 Ubuntu 24.04 为例
sudo apt update && sudo apt install -y docker.io docker-compose-plugin nginx certbot python3-certbot-nginx
sudo systemctl enable --now docker nginx
```

关闭不必要的端口：仅开放 22、80、443（服务器安全组同样放行这三个端口）。

## 2. 环境变量

在项目根目录创建 `.env`（**不要提交到 git**）：

```bash
MYSQL_ROOT_PASSWORD=请改成强随机密码
MYSQL_PASSWORD=应用数据库账号密码（同样强随机）
ADMIN_INIT_PASSWORD=首个管理员的初始密码
```

## 3. 启动

```bash
docker compose up -d --build     # 启动 MySQL + 应用
docker compose exec app npx prisma migrate deploy   # 应用数据库迁移
docker compose exec app npx tsx prisma/seed.ts      # 创建初始管理员 admin
```

应用只监听 `127.0.0.1:3000`，公网必须走 Nginx。

## 4. Nginx 反代 + HTTPS

```nginx
server {
    listen 80;
    server_name erp.example.com;
    return 301 https://$host$request_uri;   # 全站强制 HTTPS（HSTS 由应用响应头下发）
}

server {
    listen 443 ssl;
    http2 on;
    server_name erp.example.com;

    ssl_certificate     /etc/letsencrypt/live/erp.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/erp.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

证书：`sudo certbot --nginx -d erp.example.com`（自动续签）。

## 5. 备份与容灾（8.3）

### 5.1 应用内建备份（推荐，默认开启）

系统自带"定时备份 + 数据迁移"，**不需要在服务器上配 cron**：

- **自动备份**：服务每小时检查一次，距最近一份备份超过「备份周期」就自动再备一份；
  周期与保留份数在界面 **系统 → 备份与恢复** 里改（默认 24 小时一次、保留最近 14 份）。
- **手动备份**：同一页面点「立即备份」。
- **备份产物**：`backups/weichuan-backup-<UTC 时间>.json.gz`（gzip 压缩包，内含全库数据 + 清单：
  每张表行数、备份时间、格式版本）。`backups/` 目录即 compose 里挂的 `./backups`，
  **该目录已加入 `.gitignore`**，里面是完整业务数据，切勿提交到代码仓库。
- **恢复（数据迁移）**：界面里选一个 `.json.gz` 上传 → 勾选确认 → 恢复。
  恢复是**覆盖式**的（表结构不动，由 Prisma 迁移管理），且**恢复前会自动再备份一次当前数据**当退路；
  恢复后逐表核对行数，任何一张对不上就报错。恢复会把审计日志也一并还原到备份时的状态（这是"一字不差"的必然结果）。
- **异地留存**：`backups/` 建议再定期同步到对象存储或另一台机器（本机磁盘坏了就一起没了）。

也可以在宿主机用 cron 调同一套逻辑（可选，二选一即可）：

```bash
# 每小时看一次，到点才真正备份（周期仍由界面里的配置决定）
0 * * * * docker compose -f /opt/weichuan/docker-compose.yml exec -T app \
  npx tsx scripts/backup.ts --if-due >> /var/log/weichuan-backup.log 2>&1
```

命令行也支持灾难恢复（界面进不去时用）：

```bash
# 列出备份
docker compose exec app npx tsx scripts/backup.ts --list
# 从压缩包恢复（--yes 必填；恢复前会自动备份当前数据）
docker compose exec app npx tsx scripts/backup.ts --restore=weichuan-backup-2026-09-12T10-00-00Z.json.gz --yes
```

### 5.2 外部 mysqldump（可选，另一层保险）

如果希望另存一份 SQL 形态的全量备份（与上面的 JSON 包互为冗余），可用宿主机 cron：

```bash
0 2 * * * docker compose -f /opt/weichuan/docker-compose.yml exec -T mysql sh -c \
  'mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" --single-transaction weichuan_erp \
   | gzip > /backups/weichuan_erp_$(date +\%F).sql.gz'
# .env 需要在 exec 环境可见；MYSQL_ROOT_PASSWORD 变量在容器内可用
```

- 保留 30 天 + 异地留存（推荐：每日把 `/backups/*.sql.gz` 同步到云对象存储或另一磁盘/服务器）。
- 上线前演练一次"全库恢复"：`mysql < backup.sql` 到临时库，抽查单据/库存/审计。

## 6. 升级与回滚

```bash
git pull && docker compose build app && docker compose up -d app
docker compose exec app npx prisma migrate deploy   # 新迁移
```

回滚：`git checkout <上一个 tag>` → 重建镜像 → 用旧代码启动（数据库迁移只增不改，回滚不回退数据结构）。

## 9. 安全加固与日常运维（2026-09-09 起，详见《生产环境安全与运维强化计划》）

### 9.1 SSH 访问

- **仅密钥登录**，密码登录与 root 直登已禁用；运维账号 `wcadmin`（sudo 免密）。
- 私钥保管在管理员电脑 `~/.ssh/weichuan_ed25519`（**请离线备份一份**）；丢失后可用阿里云控制台 VNC 应急。
- fail2ban 生效：SSH 3 次失败封禁 1 小时，累犯封 1 周。

### 9.2 备份与恢复（GPG 加密）

| 项 | 说明 |
|---|---|
| 每日备份 | cron 02:00 执行 `scripts/backup.sh`：mysqldump → gzip → GPG(AES256) → `backups/`，保留 30 天 |
| 加密口令 | `/root/.weichuan/backup.key`（600）；**必须离线抄录一份**，丢失则备份无法恢复 |
| 备份日志 | `/var/log/weichuan-backup.log` |
| 恢复演练 | `scripts/restore.sh <备份.gpg> --db weichuan_erp_drill`（导入临时库核对，不影响生产） |
| 生产恢复 | `scripts/restore.sh <备份.gpg> --db weichuan_erp --force`（危险，先停应用） |
| 演练要求 | 每季度一次，记录在计划书执行记录中 |

### 9.3 健康检查与外部监控

- 应用健康接口：`GET /api/health` → `{"ok":true,"db":true,"backupFresh":true}`（503 = 异常）
- 外部监控：GitHub Actions `.github/workflows/uptime.yml` 每 5 分钟探测站点与健康接口，异常自动创建 Issue（仓库关注者收邮件），恢复后自动关闭。
- 建议同时在阿里云控制台开启「云监控 → 站点监控 + 主机监控」（短信/邮件双通道，更及时）。

### 9.4 主机防护

- ufw：仅放行 22/80/443；Docker 端口仅回环。
- Docker 日志轮转：单容器 10MB × 3 份。
- 系统安全补丁：unattended-upgrades 自动安装（内核更新需人工择机重启）。
