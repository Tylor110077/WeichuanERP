# 部署指南（生产）

> 依据《需求与设计文档》8.3 / 8.4：单台云服务器（2C4G 起）+ Docker + Nginx + HTTPS。
> 本文档按"全新服务器"顺序编写；服务器资源与域名待用户提供（文档 11 待办 #8）。

## 1. 服务器准备（一次性）

```bash
# 以 Ubuntu 24.04 为例
sudo apt update && sudo apt install -y docker.io docker-compose-plugin nginx certbot python3-certbot-nginx
sudo systemctl enable --now docker nginx
```

关闭不必要的端口：仅开放 22、80、443（服务器安全组同样放行这三个端口）。

把项目放到 `/opt/weichuan`——**生产线上只用得到 `docker-compose.yml`、`scripts/`、`.env`
和 `backups/`，应用镜像由 CI 构建，服务器不编译源码**。推荐直接 clone，这样后续
`git pull` 就能拿到新的运维脚本（部署脚本、HTTPS 脚本）：

```bash
sudo git clone https://github.com/Tylor110077/WeichuanERP.git /opt/weichuan
cd /opt/weichuan
```

## 2. 环境变量

在项目根目录创建 `.env`（**不要提交到 git**）：

```bash
MYSQL_ROOT_PASSWORD=请改成强随机密码
MYSQL_PASSWORD=应用数据库账号密码（同样强随机）
ADMIN_INIT_PASSWORD=首个管理员的初始密码
```

## 3. 启动

```bash
docker compose up -d          # 拉取 CI 预构建镜像并启动 MySQL + 应用（服务器不编译）
docker compose exec app npx prisma migrate deploy   # 应用数据库迁移
docker compose exec app npx tsx prisma/seed.ts      # 创建初始管理员 admin
```

应用只监听 `127.0.0.1:3000`，公网必须走 Nginx。

镜像由 CI 在云端构建后推到 `ghcr.io/tylor110077/weichuanerp`（**公开包，不需要登录**）。
默认用 `latest`，指定版本用 `APP_IMAGE`：

```bash
APP_IMAGE=ghcr.io/tylor110077/weichuanerp:sha-<完整提交号> docker compose up -d
```

**不要在服务器上 `docker compose build`**——这台机器内存小，构建会打满内存拖垮线上，
原因与替代做法见 §6。

## 4. Nginx 反代 + HTTPS

用仓库里的脚本一键完成（配置写到 `/etc/nginx/sites-available/weichuan`）：

```bash
sudo bash scripts/enable-https.sh <域名> <证书通知邮箱>
```

前置条件（缺一不可）：

1. 域名已完成 **ICP 备案**。国内服务器访问 80/443 的前提；未备案时阿里云在网络边缘直接
   返回 `403 Non-compliance ICP Filing`（响应头 `Server: Beaver`），**连 Let's Encrypt 的
   校验请求也进不来**，证书申请必然失败。
2. 域名 A 记录已解析到本机公网 IP（`@` 与 `www` 都指过来）。
3. 安全组 / ufw 放行 80、443。

脚本做的事：安装 certbot → 写 HTTP 校验配置 → 申请证书 → 写完整 HTTPS 配置
（80 全量 301 跳 443、TLS1.2+、OCSP stapling、登录接口限流）→ 校验并热加载 nginx →
检查自动续签。证书申请失败时脚本会退出并给出排查方向，可重复执行（幂等）。

⚠️ HTTPS 生效后，**用 IP 访问 HTTP 会被 301 跳到 `https://<域名>`**：团队收藏夹里的
`http://47.108.181.80` 要改成 `https://<域名>`；`.github/workflows/uptime.yml` 的探测地址
也要同步改（见 §9.5）。

## 5. 备份与容灾（8.3）

### 5.1 应用内建备份（推荐，默认开启）

系统自带"定时备份 + 数据迁移"，**不需要在服务器上配 cron**：

- **自动备份**：服务每小时检查一次，距最近一份备份超过「备份周期」就自动再备一份；
  周期与保留份数在界面 **系统 → 备份与恢复** 里改（默认 24 小时一次、保留最近 14 份）。
- **手动备份**：同一页面点「立即备份」。
- **备份产物**：`backups/weichuan-backup-<UTC 时间>.json.gz`（gzip 压缩包，内含全库数据 + 清单：
  每张表行数、备份时间、格式版本）。`backups/` 目录即 compose 里挂的 `./backups`，
  **该目录已加入 `.gitignore`**，里面是完整业务数据，切勿提交到代码仓库。
- **恢复（数据迁移）**：界面里选一个 `.json.gz` 上传 → 勾选确认 → 恢复。
  恢复是**覆盖式**的（表结构不动，由 Prisma 迁移管理），且**恢复前会自动再备份一次当前数据**当退路；
  恢复后逐表核对行数，任何一张对不上就报错。恢复会把审计日志也一并还原到备份时的状态（这是"一字不差"的必然结果）。
- **异地留存**：`backups/` 建议再定期同步到对象存储或另一台机器（本机磁盘坏了就一起没了）。

也可以在宿主机用 cron 调同一套逻辑（可选，二选一即可）：

```bash
# 每小时看一次，到点才真正备份（周期仍由界面里的配置决定）
0 * * * * docker compose -f /opt/weichuan/docker-compose.yml exec -T app \
  npx tsx scripts/backup.ts --if-due >> /var/log/weichuan-backup.log 2>&1
```

命令行也支持灾难恢复（界面进不去时用）：

```bash
# 列出备份
docker compose exec app npx tsx scripts/backup.ts --list
# 从压缩包恢复（--yes 必填；恢复前会自动备份当前数据）
docker compose exec app npx tsx scripts/backup.ts --restore=weichuan-backup-2026-09-12T10-00-00Z.json.gz --yes
```

### 5.2 外部 mysqldump（可选，另一层保险）

如果希望另存一份 SQL 形态的全量备份（与上面的 JSON 包互为冗余），可用宿主机 cron：

```bash
0 2 * * * docker compose -f /opt/weichuan/docker-compose.yml exec -T mysql sh -c \
  'mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" --single-transaction weichuan_erp \
   | gzip > /backups/weichuan_erp_$(date +\%F).sql.gz'
# .env 需要在 exec 环境可见；MYSQL_ROOT_PASSWORD 变量在容器内可用
```

- 保留 30 天 + 异地留存（推荐：每日把 `/backups/*.sql.gz` 同步到云对象存储或另一磁盘/服务器）。
- 上线前演练一次"全库恢复"：`mysql < backup.sql` 到临时库，抽查单据/库存/审计。

## 6. 升级与回滚

**服务器上不编译**（原因同 §3）。升级 = CI 在云端构建镜像 → 服务器只拉取：

1. 推送代码到 `main`，`.github/workflows/build-image.yml` 自动构建 `linux/amd64` 镜像，
   推送到 `ghcr.io/tylor110077/weichuanerp`，标签为 `sha-<完整提交号>` 与 `latest`。
2. 服务器上跑部署脚本（拉取 + 迁移 + 切换 + 健康检查，**失败自动回滚**）：

```bash
sudo bash scripts/deploy.sh sha-<完整提交号>   # 推荐：精确到提交，可回滚
sudo bash scripts/deploy.sh                    # 或部署 latest（CI 最新构建）
sudo bash scripts/deploy.sh --rollback         # 回滚到上一次部署成功的镜像
sudo bash scripts/deploy.sh --list             # 看历史部署记录（保留最近 10 条）
```

脚本的执行顺序：记录回滚点 → 部署前自动备份 → 拉镜像 → **用新镜像跑
`prisma migrate deploy`（此时旧容器仍在服务，迁移不占用线上）** → 切换应用容器 →
健康检查（`/api/health`）→ 记录本次部署。任一步失败、或健康检查不过，脚本会切回
上一个镜像并重新验证；回滚后仍不健康会打印排查命令并以非 0 退出。

手工等价操作（脚本不可用时的兜底）：

```bash
docker compose pull app
docker compose run -T --rm --no-deps app npx prisma migrate deploy
APP_IMAGE=ghcr.io/tylor110077/weichuanerp:sha-<提交号> docker compose up -d app
curl -fsS http://127.0.0.1:3000/api/health
```

回滚：`APP_IMAGE=<上一个镜像> docker compose up -d app`。数据库迁移**只增不改**，
回滚不回退表结构——旧代码要能容忍多出来的新字段。

自建镜像（不推荐，仅 CI 不可用时）：把 `docker-compose.yml` 里 app 的 `image:` 换成
`build: .`，再 `docker compose build app && docker compose up -d app`。这会在这台机器上
编译，2G 内存的机器可能 OOM——动手前先确认可用内存，必要时临时加 swap。

## 9. 安全加固与日常运维（2026-09-09 起，详见《生产环境安全与运维强化计划》）

### 9.1 SSH 访问

- **仅密钥登录**，密码登录与 root 直登已禁用；运维账号 `wcadmin`（sudo 免密）。
- 私钥保管在管理员电脑 `~/.ssh/weichuan_ed25519`（**请离线备份一份**）；丢失后可用阿里云控制台 VNC 应急。
- fail2ban 生效：SSH 3 次失败封禁 1 小时，累犯封 1 周。
- ⚠️ **别拿 SSH 当探针**（2026-09-22 实测教训）：用 `root@` 试一次、再连两次，3 次失败就把
  自己的出口 IP 封了——端口探针只能看到 `Connection refused`，看起来像"服务器挂了"，
  实则是本机 IP 被拒。封禁期间 22 端口对**其他**节点仍通（可用 `https://check-host.net/check-tcp`
  从外部节点核实，避免误判为服务器故障）。
  解封：阿里云控制台 → ECS → 远程连接/云助手 →
  `fail2ban-client status sshd` 看封了谁，`fail2ban-client set sshd unbanip <IP>` 解封；
  常用出口 IP 建议加进 `/etc/fail2ban/jail.local` 的 `ignoreip`。

### 9.2 备份与恢复（GPG 加密）

| 项 | 说明 |
|---|---|
| 每日备份 | cron 02:00 执行 `scripts/backup.sh`：mysqldump → gzip → GPG(AES256) → `backups/`，保留 30 天 |
| 加密口令 | `/root/.weichuan/backup.key`（600）；**必须离线抄录一份**，丢失则备份无法恢复 |
| 备份日志 | `/var/log/weichuan-backup.log` |
| 恢复演练 | `scripts/restore.sh <备份.gpg> --db weichuan_erp_drill`（导入临时库核对，不影响生产） |
| 生产恢复 | `scripts/restore.sh <备份.gpg> --db weichuan_erp --force`（危险，先停应用） |
| 演练要求 | 每季度一次，记录在计划书执行记录中 |

### 9.3 健康检查与外部监控

- 应用健康接口：`GET /api/health` → `{"ok":true,"db":true,"backupFresh":true}`（503 = 异常）
- 外部监控：GitHub Actions `.github/workflows/uptime.yml` 每 5 分钟探测站点与健康接口，异常自动创建 Issue（仓库关注者收邮件），恢复后自动关闭。
- 建议同时在阿里云控制台开启「云监控 → 站点监控 + 主机监控」（短信/邮件双通道，更及时）。

### 9.4 主机防护

- ufw：仅放行 22/80/443；Docker 端口仅回环。
- Docker 日志轮转：单容器 10MB × 3 份。
- 系统安全补丁：unattended-upgrades 自动安装（内核更新需人工择机重启）。
