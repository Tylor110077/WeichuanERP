## 1. 现状盘点（实测）

| 项 | 实测结果 | 影响 |
|---|---|---|
| 页面总数 | 36 个 | 一次性全改不现实，需分期 |
| 布局骨架 | `<aside className="w-52">` 固定 208px 侧边栏，**无任何响应式类** | 手机上侧边栏吃掉 55% 屏宽（375px 屏仅剩 167px 内容区），**基本不可用** |
| 响应式类使用量 | `sm:` 9 处、`md:` 1 处、`lg:` 8 处（36 个页面） | 全站等于没有做响应式 |
| 表格 | 25 个页面含表格，24 个已包 `overflow-x-auto` | 好消息：不会破版；坏消息：手机上要左右拖，列多时难以定位 |
| 开单页表格 | 9 列固定宽度（编码 28 + 名称 256 + 库存 20 + 数量 28 + 单位 16 + 售价 32 + 补货 72 + 金额 28 + 删除 14）≈ 500px+ | 手机上必须横向滚动，录入体验差 |
| 登录页 | `max-w-sm` 居中、单列表单 | 天然适配，无需改造 |
| 筛选栏 | `flex flex-wrap` 换行布局 | 基本可用，仅需调整触摸尺寸 |
| 图表 | 纯 SVG + `viewBox`（价格分析、销售分析） | 宽度自适应，仅需调整高度与字号 |
| viewport | 依赖 Next.js 默认注入 | 需显式声明并放开缩放（可访问性） |

**结论**：不是"优化"，而是"补齐移动端形态"——导航骨架、表格形态、触摸尺寸三件事必须做。

## 2. 使用场景与优先级（**需确认**）

> 以下为基于业务角色的推断，请评审确认或修正；场景直接决定分期顺序。

| 优先级 | 场景 | 角色 | 使用频率 | 对应页面 |
|---|---|---|---|---|
| **最高** | 现场开售卖单（含缺货自动补货） | 业务员 | 每天多次 | 售卖开单 |
| **最高** | 查库存、查历史售价、查上次给某客户的价格 | 业务员 | 每天多次 | 库存查询、商品管理 |
| **高** | 看单据列表与详情（我今天开了什么） | 业务员 | 每天 | 售卖单列表/详情、进货单列表/详情 |
| **高** | 查客户欠款、登记收款 | 老板/财务 | 每周 | 应收应付、客户画像 |
| **中** | 看经营数据（今日销售额、利润、价格走势） | 老板 | 每周 | 工作台、销售分析、价格分析、报表 |
| **中** | 进货开单、退货 | 业务员 | 每周 | 进货开单、退货单 |
| **低** | 基础资料维护（商品/客户/供应商/单位） | 管理员 | 每月 | 基础资料各页 |
| **低** | 用户管理、审计日志、行情 | 管理员 | 偶尔 | 系统各页 |
| **不适用** | 打印小票/发货单 | — | — | 打印预览（手机上仅做提示，保留查看） |

**建议一期范围**：业务员的「查 + 开单」闭环 + 老板的「看数」——覆盖 80% 的手机使用价值。

## 3. 技术方案

### 3.1 导航骨架（最关键）

**方案：移动端抽屉 + 桌面端不变**

| 断点 | 形态 |
|---|---|
| `< 768px`（手机/竖屏平板） | 顶部 sticky 栏（左侧汉堡菜单 + 页面标题 + 右侧用户入口）；点击汉堡从左侧滑出抽屉（含完整分组导航），带半透明遮罩，点击遮罩或选中项后关闭 |
| `≥ 768px`（桌面/横屏平板） | 保持现有固定侧边栏 208px，**零改动** |

实现要点：
- 抽屉状态由 client 组件管理；打开时锁定页面滚动（`overflow: hidden`），关闭时恢复
- 当前页高亮逻辑复用现有实现（含 `?query` 最长匹配）
- 抽屉内导航项触摸高度 ≥48px
- 桌面端渲染路径完全不变，避免回归风险

**备选（可在 P1 评估）**：底部标签栏（工作台 / 开单 / 库存 / 单据 / 我的）——移动端更顺手，但需与抽屉二选一或组合（底部标签 + 抽屉放全部菜单）。

### 3.2 表格策略（按页面分三档）

| 档位 | 页面类型 | 移动端形态 |
|---|---|---|
| A. 卡片化 | 列少、行独立的列表：库存查询、客户/供应商/商品列表、单位/分类 | 断点以下改为卡片列表（标题 + 2~3 个关键字段 + 右侧金额），信息密度与可读性兼顾 |
| B. 横向滚动 + 关键列优先 | 单据列表、库存流水、审计日志、报表 | 保留 `overflow-x-auto`，增加：首列（单号/名称）`sticky left-0` 便于定位；列宽与字号在移动端压缩；表格外加"左右滑动查看"提示 |
| C. 卡片式行编辑 | 售卖开单、进货开单、退货单（多列录入） | 每个商品行渲染为一张卡片：商品名 + 数量 / 单价 / 单位 / 金额在同一卡片内分两行排布；缺货补货信息在卡片内以浅色区块展示。**这是工作量最大、价值也最高的一项** |

### 3.3 表单与触摸交互

| 项 | 规范 |
|---|---|
| 表单栅格 | `grid-cols-1 md:grid-cols-2`（现有多为 `grid-cols-2` 固定两列，手机上过窄） |
| 触摸目标 | 按钮/输入框/可点行高度 ≥44px（当前多为 32~36px） |
| 输入框字号 | ≥16px（低于 16px 时 iOS Safari 聚焦会自动放大页面） |
| 数字输入 | 数量/金额输入框加 `inputMode="decimal"`，唤起数字键盘；`.spinner` 已隐藏，保持 |
| 日期选择 | `type="date"` 移动端原生控件已可用；快捷条（今日/本周）改为可横向滚动的一行 |
| 反馈 | 提交按钮 `pending` 态需明显（已有）；操作成功提示在移动端需可见（避免被键盘遮挡） |
| 候选弹层 | 商品/客户搜索候选层在手机上改为全宽列表，项高 ≥48px |

### 3.4 图表与可视化

- SVG 图表无需改造（`viewBox` 自适应）；移动端降低高度（230→180）并减少 X 轴标签数量（首/中/尾 → 首/尾）
- 价格分析悬浮提示在触摸设备改为**点击显示**（触摸无 hover），点击空白处关闭
- KPI 卡片：`grid-cols-2` 在手机上保持两列（数字类信息两列可读性好），字号下调一档

### 3.5 PWA（可选，P1 建议）

- 添加 `manifest.json` + 图标：支持"添加到主屏幕"，打开即为全屏应用观感
- **不做离线缓存**（业务系统数据实时性要求高，离线意义有限且易造成数据误导）
- 不加 Service Worker 的复杂缓存策略，避免升级后旧资源残留

### 3.6 打印相关

- 打印预览页在手机端保留查看能力，但顶部提示"建议在电脑上打印效果最佳"
- 不实现手机打印（浏览器打印排版不可控，投入产出比低）

## 5. 验收标准（可量化）

| 维度 | 标准 | 验证方式 |
|---|---|---|
| 无横向溢出 | 375px 宽度下 `document.documentElement.scrollWidth <= 客户端宽度` | 逐页脚本检查 |
| 触摸可用 | 所有可点元素 ≥44×44px | 抽查 + 脚本统计 |
| 无自动缩放 | 输入框 `font-size ≥ 16px` | 抽查 |
| 核心流程 | 手机完成"登录→查库存→开卖单（含缺货补货）"全流程无阻塞 | 真机/模拟器实操 |
| 桌面端无回归 | 1440px 下与改造前视觉一致 | 改造前后截图对比 |
| 响应速度 | 移动网络（4G 模拟）首屏可交互 < 3s | Lighthouse 移动端 |

**测试设备矩阵**：iPhone SE（375×667，最小）、iPhone 15（393×852）、Android 中端（412×915）、iPad 竖屏（768×1024）。

## 6. 测试与回归防护

1. **断点隔离原则**：所有移动端改动使用 `md:` 以下断点（默认样式即移动端 + `md:` 还原桌面），保证桌面端渲染路径不变
2. **截图基线**：改造前对 36 个页面分别截桌面（1440px）与手机（375px）基线图，改造后逐页对比
3. **自动化检查**：写一个页面扫描脚本，用 Playwright 逐页断言"无横向溢出 + 触摸目标尺寸"，纳入 P0 验收
4. **真机验证**：至少用一台真实手机验证（浏览器缩放模拟无法暴露 iOS 输入框缩放、`position: fixed` 键盘挤压等问题）
5. **变更分批上线**：P0、P1、P2 各自独立部署，每批验收后再进行下一批

## 7. 风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| 开单页卡片化重构面大 | 可能影响现有开单流程（核心业务） | 桌面端保持表格形态不动，仅移动端走卡片；改造后回归测试开单全流程（含缺货补货、成本快照） |
| 响应式改动波及桌面端 | 桌面用户（主要使用场景）体验回退 | 断点隔离 + 截图基线对比 + 分批上线 |
| 移动端与桌面端交互差异积累 | 后续维护成本上升 | 抽出共用组件（表格/表单/导航），避免同一逻辑两套实现 |
| 手机端网络环境 | 4G 下首屏慢 | 首屏资源已由 Next.js 优化；如仍慢，评估图片/字体进一步压缩 |
| 屏幕尺寸长尾 | 大屏手机/折叠屏显示异常 | 使用流式布局（避免固定像素宽），设置合理的 `max-width` |

**依赖与待确认项**（未确认时按下表默认方案执行）：

| # | 待确认 | 默认方案 | 影响 |
|---|---|---|---|
| 1 | 手机端主要使用场景 | **业务员开单 + 查询优先**（P0/P1 按第 4 章顺序）；老板看数放 P2 | 决定分期顺序，不影响总体方案 |
| 2 | 导航形态 | **抽屉式侧边菜单**（与桌面端菜单一致，改动最小、无菜单数量限制）；P1 评估是否追加底部标签栏 | 影响 P0 工作量约 ±0.5 天 |
| 3 | 是否要 PWA（添加到主屏幕） | **要**（列 P1）；不做离线缓存 | 影响 P1 工作量约 0.5 天 |
| 4 | 真机验收设备 | iPhone（375px 最小宽度）+ 一台 Android 中端 | 决定验收环境 |
| 5 | HTTPS 上线时间 | 备案完成后（手机浏览器在 HTTP 下部分能力受限，不影响基本使用） | 影响真机验收时机 |
