## 1. 现状盘点

### 1.1 已具备（无需重复建设）

| 能力 | 现状 |
|---|---|
| 密码存储 | argon2id + 随机盐；用户不存在时等时校验防枚举 |
| 会话安全 | Cookie 仅存随机 token，库内只存 sha256；HttpOnly + SameSite=Lax + 生产 Secure；8 小时有效期；停用用户即时吊销全部会话；改密吊销其他会话 |
| 登录防护 | 单账号 5 次失败锁 15 分钟；登录成功/失败均写 login_logs |
| 权限 | 后端守卫（requireAdmin / requireMasterDataWrite / requireLogin），前端仅展示控制 |
| 审计 | 关键动作含变更前后快照、操作人、IP（Nginx 传 X-Forwarded-For）；无删除接口 |
| 应用安全头 | CSP、X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy；生产 HSTS |
| 网络暴露面 | 公网仅 22 / 80（443 待启用）；应用 3000 仅回环；MySQL 3306 未对外 |
| 系统补丁 | unattended-upgrades 已启用 |
| 每日备份 | cron 每日 02:00 mysqldump（gzip），本机 `/opt/weichuan/backups/`，保留 30 天 |

### 1.2 已识别风险（本计划要解决的）

| # | 风险 | 严重度 | 现状事实 |
|---|---|---|---|
| R1 | **全站 HTTP 明文**，登录密码可被链路嗅探 | 严重 | 未配 HTTPS（等域名/备案） |
| R2 | **SSH 允许 root + 密码登录**，且密码强度低、已在会话中传递 | 严重 | `PermitRootLogin yes`、`PasswordAuthentication yes`、MaxAuthTries 6 |
| R3 | **备份与生产同机**，服务器损毁则数据与备份同时丢失 | 严重 | 备份仅在本机磁盘 |
| R4 | 无入侵检测/自动封禁，SSH 与 Web 可被暴力破解 | 高 | fail2ban 未安装 |
| R5 | 主机防火墙未启用（依赖云控制台规则，未文档化） | 中 | `ufw status: inactive` |
| R6 | 登录限流只按账号，不按 IP：可撞库其他账号、也可恶意锁死他人账号 | 高 | 仅 `getLockRemainingSeconds(userId)` |
| R7 | Nginx 无限流、未隐藏版本号 | 中 | 默认配置 + 反代 |
| R8 | `.env`（数据库/管理员密码）权限 644，任何本地用户可读 | 中 | `-rw-r--r--` |
| R9 | Docker 容器日志无上限，长期运行可能写满磁盘 | 中 | 默认 json-file 无限制 |
| R10 | 无监控告警：宕机、磁盘满、备份失败无人知晓 | 高 | 无云监控/站点监控配置 |
| R11 | 应用容器无 healthcheck，进程假死不会被发现 | 中 | compose 未定义 |
| R12 | 审计日志可被应用账号删除（若应用被攻陷可灭迹） | 中 | 应用 DB 账号对 audit_logs 有 DELETE 权限 |
| R13 | 无整机快照，误操作/勒索无快速回退手段 | 中 | 未开启自动快照 |
| R14 | 依赖漏洞无跟踪机制 | 中 | 无 Dependabot / 定期 npm audit |
| R15 | 恢复流程从未演练，"备份可用"只是假设 | 高 | 无演练记录 |

## 3. 分项强化计划

> 优先级：P0 = 本周内（不依赖域名）；P1 = 1~2 周；P2 = 1~3 个月或按需。

### 3.1 A. 网络与边界安全

| 项 | 措施 | 优先级 | 验收标准 |
|---|---|---|---|
| A1 | **启用 HTTPS**：域名备案完成后，Let's Encrypt 证书 + 443 + HTTP 301 跳转；仅保留 80/443/22；HSTS 生效 | P0（依赖备案） | `https://域名` 绿锁、http 自动跳转、SSLLabs A 级 |
| A2 | **SSH 加固**：改用密钥登录（生成密钥对、禁用密码登录）、禁止 root 直登（用普通用户 + sudo）、MaxAuthTries 降至 3、可选改非标端口 | P0 | 密码登录被拒、密钥可登录、`sshd -T` 核对 |
| A3 | **SSH 来源白名单**：云防火墙仅放行公司固定出口 IP（若办公网有固定 IP）；否则至少限制为国内段 | P0 | 非白名单 IP 连接超时 |
| A4 | **fail2ban**：sshd 3 次失败封 1 小时；Nginx 401/403/登录失败路径限速封禁 | P0 | 模拟爆破被自动封禁 |
| A5 | **云防火墙文档化**：确认轻量控制台仅放行 22/80/443，关闭其余；服务器侧 ufw 作为第二道防线（仅允许上述端口 + Docker 内部） | P0 | 外部端口扫描仅 22/80/443 开放 |
| A6 | **Nginx 加固**：`server_tokens off`、`limit_req`（登录等写接口 5r/s burst）、`limit_conn`、请求体 1M 限制、超时收敛 | P1 | 压测触发 429/503，版本号不泄露 |
| A7 | **应用层登录 IP 限流**：同一 IP 5 分钟内 ≥20 次登录尝试即临时拒绝（代码改造）；账号锁定逻辑保留 | P0 | 脚本撞库被 IP 级拦截 |
| A8 | DDoS：阿里云基础防护默认生效；若遭攻击再评估高防/WAF | P2 | 按需 |

### 3.2 B. 身份与应用安全

| 项 | 措施 | 优先级 | 验收标准 |
|---|---|---|---|
| B1 | 修改初始管理员密码（部署时随机生成，仍需首登更换） | P0 | 个人中心改密成功 |
| B2 | 密码策略升级：≥12 位、含大小写+数字+符号；改密频率提示（不强制定期换） | P2 | 新建/改密被校验 |
| B3 | 依赖漏洞治理：开启 GitHub Dependabot；每月 `npm audit` 复盘 | P1 | 告警可查、高危 7 天内修复 |
| B4 | 审计防篡改：为 `audit_logs` 加数据库触发器禁止 DELETE/UPDATE；或拆分"迁移账号/运行账号"权限 | P1 | 应用账号执行 DELETE 被拒 |

| B6 | CSRF：确认 Next.js Server Actions 的 Origin 校验在生产生效（Next 16 默认内置）；Cookie SameSite=Lax 作为补充 | P1 | 跨站伪造请求被拒 |
| B7 | 错误信息收敛：生产环境不向用户回显堆栈/SQL 细节 | P1 | 抽查异常页面 |
| B8 | 可选 2FA：管理员账号启用 TOTP（Google Authenticator） | P2 | 登录需动态码 |
| B9 | 账号生命周期：离职/调岗当日停用账号并吊销会话（现有停用即吊销机制） | 流程项 | 台账可查 |
| B10 | 数据库账号最小权限：运行账号仅 DML，迁移用独立账号（含 DDL） | P2 | 权限矩阵核对 |

## 4. 备份与容灾专项设计

### 4.1 目标指标

| 指标 | 现状 | 目标 |
|---|---|---|
| RPO（可容忍数据丢失） | 24 小时 | **≤24h（P0）**；P2 提升至 ≤1h（binlog 时间点恢复） |
| RTO（恢复时长） | 未验证 | **≤1 小时** |
| 备份保留 | 本机 30 天 | 本机 30 天 + 异地 90 天 + 每月归档 1 年 |
| 演练 | 无 | 每季度 1 次恢复演练 |

### 4.2 3-2-1 原则落地

| 副本 | 载体 | 位置 | 内容 | 周期 |
|---|---|---|---|---|
| 副本 1（生产） | 云盘 | 服务器 | MySQL 数据 | 实时 |
| 副本 2（本机备份） | 服务器磁盘 `/opt/weichuan/backups` | 同机 | mysqldump gzip | 每日 02:00，保留 30 天 |
| 副本 3（异地） | 阿里云 OSS（独立 Bucket） | 异地/跨地域 | 加密后的备份文件 | 每日同步，保留 90 天；每月 1 日归档保留 1 年 |
| 副本 4（整机） | 阿里云自动快照 | 同地域 | 系统盘整机 | 每日 1 次，保留 7 天 |

### 4.3 实施要点

1. **OSS 异地备份**（P0）
   - 独立 Bucket，**私有读写**，开启**服务端加密（SSE-KMS）**与**版本控制**；
   - 服务器装 ossutil，cron 每日 03:00 把 `/opt/weichuan/backups/*.sql.gz` 同步上去；
   - Bucket 配置**生命周期规则**（90 天转低频/删除，归档每月保留）；
   - 建议 Bucket 与服务器**不同地域**（如服务器成都 → Bucket 上海），防地域级故障。
2. **备份文件加密**（P0）：除 OSS 服务端加密外，本地 gzip 前用 GPG 对称加密（口令单独保管，不写在服务器上），防止备份文件泄漏即数据泄漏。
3. **恢复演练**（P1，之后每季度）
   - 在临时目录起一个 MySQL 容器 → 导入最新备份 → 抽查单据/库存/审计表行数与金额勾稽；
   - 记录演练时间与结果，形成《恢复演练记录》。
4. **备份监控**（P0）：备份脚本失败即触发告警；每日检查 OSS 上当日文件是否存在。
5. **配置与密钥备份**（P1）：`.env`、Nginx 配置、证书私钥单独加密留存（离线保管），避免"服务器重建后密码全丢"。
6. **审计日志保留**（P1）：审计表随每日备份进入 OSS，保留 ≥2 年（满足需求文档 8.3）。

### 4.4 恢复流程（RTO ≤ 1h）

```
1. 新服务器：装 Docker → git clone → 恢复 .env（离线保管的加密文件）
2. docker compose up -d mysql（先起库）
3. 从 OSS 取最新备份 → gunzip + GPG 解密 → 导入 MySQL
4. docker compose up -d app → 验证登录与关键页面
5. 切换 DNS / 更新访问地址 → 通知用户
```
