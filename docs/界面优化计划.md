## 2. 优化方案

### P0 — 建立规则并消除不一致（纯样式，零功能风险）

| # | 措施 | 具体做法 | 验证 |
|---|---|---|---|
| P0-1 | **按钮统一为 4 档** | 主：`h-9 px-4 text-sm 蓝底`；次：`h-9 px-4 text-sm 描边`；危险：`h-9 px-4 text-sm 红描边`；行内小按钮：`h-8 px-3 text-xs 描边`。全站替换（约 90 处） | grep 后仅剩 4 种尺寸 |
| P0-2 | **返回链接统一** | 详情页右上角用「次按钮」；表单页底部用统一的「← 返回列表」文字链 | 抽查 12 处 |
| P0-3 | **空状态统一组件** | 建 `EmptyState`：图标 + 主文案 + 可选引导按钮（"去创建商品"等），替换 39 处 | 组件唯一来源 |
| P0-4 | **危险操作统一** | 作废/删除：红描边按钮 + 二次确认文案；行内删除用低调文字按钮 | 抽查 |
| P0-5 | **间距节奏** | 页面级容器间距统一 `space-y-6`；卡片内 `p-5`；表格内边距 `px-4 py-2.5` | 抽查 |

### P1 — 交互一致性（把"要思考"变成"下意识"）

| # | 措施 | 具体做法 |
|---|---|---|
| P1-1 | **筛选统一交互** | 下拉/日期选择 → **选完即筛**（自动跳转）；文本输入（单号/关键词）→ **回车即筛**；保留「查询」按钮作为可见兜底。全站统一，不再混用 |
| P1-2 | **筛选条件跨页保留** | 分页/快捷时间/视图切换均保留全部筛选（已部分完成，补齐其余页面） |
| P1-3 | **提交后去向统一** | 新建/编辑表单 → 提交后回列表页并提示成功；单据操作（作废/退货/收付款）→ 停留在当前详情页并刷新 |
| P1-4 | **列表行加常用操作** | 单据列表行内直接提供「详情 / 登记」；库存行提供「批次」；商品行提供「编辑」——减少一次跳转 |

### P2 — 符合直觉

| # | 措施 | 具体做法 |
|---|---|---|
| P2-1 | **术语统一为「厂家」** | 表单/表格中「供应商」文案统一为「厂家」（数据库字段名不动，仅界面文案） |
| P2-2 | **空状态带引导** | 无数据时说明"为什么空 + 下一步做什么"，如"还没有商品，先去创建" |
| P2-3 | **页面标题区统一** | 所有页面统一为「标题 +（右侧）本页主操作按钮」，位置与样式一致 |
| P2-4 | **成功/失败反馈统一** | 所有写操作给出明确反馈（绿色成功 / 红色失败），位置统一在操作按钮旁 |

### P3 — 审美细节

| # | 措施 | 具体做法 |
|---|---|---|
| P3-1 | **颜色语义规范** | 红＝负向（未结清、负库存、亏损）；绿＝正向（已结清、盈利）；橙＝待处理（待收货、预警）；灰＝中性 |
| P3-2 | **表格密度与对齐** | 统一 `[&_td]:align-top [&_th]:whitespace-nowrap`（已部分完成），数字右对齐、文本左对齐 |
| P3-3 | **选中/悬停反馈** | 行悬停浅灰底、当前导航项高亮（已有），补齐列表行与卡片的悬停态 |

## 9. 补充约定：搜索框与选择器「点开即全选」（2026-09-12）

**问题（用户反馈）**：所有带搜索的小框，点进去里面还留着上次的文字，直接打字会**追加**
（"李燕芬" + "张" → "李燕芬张"），搜不到东西，必须先手动删掉——大部分搜索框都有这个毛病。

**原因**：两类控件都会保留上一次的值——
① 筛选框用 `defaultValue={q}` 回填当前筛选词；
② 选择器（SearchSelect / 开单页的客户、商品选择）把"已选名称"留在输入框里。
两者都只在 `focus` 时打开候选列表，没有处理"框里已有文字"的情况。

**约定**：搜索框与选择器在**focus 与 click 时都全选已有文字**，打字即替换。
只用 focus 不够——**已聚焦的框再点一次不会再触发 focus**，光标会落到点击位置，打字照样是追加，
而这恰恰是最常见的操作路径。

**实现**：
- `src/components/select-all-on-focus.ts`：`selectAllOnFocus` / `selectAllOnClick` 两个处理器（并注明为什么两个都要）。
- `src/components/search-input.tsx`：`SearchInput` 客户端组件（筛选页是服务端组件，不能直接给元素传 onFocus），
  5 个筛选页（售卖单、进货单、库存查询、客户、商品）改用它。
- `SearchSelect`、开单页的客户/商品选择器、主从布局左栏搜索框：均补上 click 全选。

**验证（浏览器实测）**：筛选框 `/sale-orders?q=2026` 与 `/customers?q=李`：
聚焦即全选，打字后值变为新关键词（不再拼接）；
开单页选中「李燕芬」后再点击输入框：全选 → 打字变为「张」；
应收应付对象筛选（SearchSelect）与商品页左栏搜索：同样通过。

## 10. 补充约定：控件高度统一与「提示不得参与行内布局」（2026-09-12）

**问题（用户多次反馈）**：界面上时不时出现"没对齐"。排查后确认是**同一类原因反复出现**，共两条：

1. **提示文字参与了行内布局。** 例如选择器在输入框下面显示「请从候选中点选」，
   这个控件就比同一行的其它控件高一行；筛选栏按底部对齐（`items-end`）后，整行控件顶部全部错开。
   同样的坑此前已在两处出现过：开单页客户字段的提示、进货单入库提示把按钮挤到下一行。
2. **控件高度本来就不一致。** 筛选栏里输入框有 `px-2 py-1.5`（约 34px）、
   选择器是 `px-3 py-2`（约 38px）、按钮是 h-8/h-9，混在一行里即使底部对齐，顶部也会差几个像素。

**统一约定**

- 输入框/下拉一律用 `src/lib/ui.ts` 的 `inputBase` / `selectCls`（固定 **h-9 = 36px**，与 `btnSecondary` 同高）；
  局部若还要包一层（如 `mt-1 w-full`），也必须基于 `inputBase` 拼，不要再写裸类名。
- **任何"提示 / 报错 / 计数"文字都不得放进对齐行内**：
  - 选择器的"未选中"提示 → 放进它的下拉面板里（`SearchSelect` 已改）；
  - 字段级提示 → 放到整行**下方**并预留固定高度（开单页客户字段已改）；
  - 区块级提示 → 用整行的 `FormAlert` / `basis-full`（单据详情已改）。
- 复选框等小控件与同行控件**同中线**：外面套 `flex h-9 items-center`。

**本次落地**：`inputBase`/`selectCls` 令牌 + 替换 13 个文件的筛选栏输入框、`SearchSelect`、
4 处局部输入框常量、库存页复选框行高。

**验证方法（可复用）**：在浏览器里量同一行控件的 `top / bottom / 中线`：
- 10 个列表页筛选栏：控件高度全为 36，`top` 与 `bottom` 各自唯一（完全齐平）；
- 开单页客户行：输入框 36 / 按钮 32，但**中线一致**；
- 库存页：搜索框、复选框、筛选按钮中线均为 111。

## 11. 补充约定：表单标签只写字段名，说明性文字进 placeholder（2026-09-12）

**问题**（用户反馈「编辑客户时，所属组织的编辑跟其他格式不一样」）

同一个表单里，标签有两种写法：

- 多数字段：`客户名称 *`、`联系人`、`电话` —— 干净；
- 少数字段：`所属组织（改组织即移动，可搜索）`、`标签（可多选）`、`厂家 *（缺货时自动向其补货，可当场新建）`
  —— 把一句说明塞进了标签。

后果有三：同排字段的标签一长一短，标签行看起来不齐；括号里的话是"使用说明"，
不属于字段名；同一字段在不同页面（客户编辑页 / 客户列表内联表单 / 开单页快捷新建）
括号里的措辞还不一样，同一个功能有三种说法。

**统一约定**

- **标签只写字段名**，必填加 `*`（如 `所属组织`、`标签`、`厂家 *`、`商品名称 *`）。
- **说明性文字一律放 `placeholder`**：用户正要输入时才需要看它，且天然不占额外高度、
  不影响标签行长度。例：
  - `所属组织` → placeholder「改组织即移动，输入关键词搜索」
  - `厂家 *` → placeholder「缺货时自动向其补货，可当场新建」
  - `商品名称 *` → placeholder「完整名称，含规格，如：BV 2.5平方 单芯铜线」
  - `库存预警线` → placeholder「留空按 1 计」
- 例外：**筛选栏**的 `进货时间（起）/（止）`、`开始（默认本月 1 日）` 这类是筛选条件的限定语，
  不是字段说明，保留原样；区块标题下的 hint（`SectionHeading` 的 hint 属性）也保留。
- 字段说明若承载了业务规则（如"缺货自动补货"），**不要只留在 placeholder 里**
  —— placeholder 在已有值时不可见，因此在页面标题（h1）或区块 hint 里保留一份。

**本次落地**：客户（编辑页 / 新建页 / 列表内联表单）、商品（编辑页 / 新建页 / 列表内联表单）、
开单页快捷新建商品面板，共 6 个文件、15 处标签。`EntityForm` 的 searchselect 与 manufacturer
两个分支补上了 placeholder 透传（原先只有纯文本字段支持）。

**验证**：`/customers/4`、`/customers/new`、`/products/new`、`/products/1` 四个表单实测标签
已无括号、提示在 placeholder 里；所有控件仍为 `357×36`，`left/top` 与改动前逐一对齐。
