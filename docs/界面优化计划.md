# 网页设计优化计划书

| 项目 | 内容 |
|---|---|
| 版本 | v1.0（待评审） |
| 日期 | 2026-09-12 |
| 范围 | 36 个页面（工作台 / 进货 / 销售 / 库存 / 财务 / 基础资料 / 系统） |
| 原则 | **不减少任何功能**；只做一致性、可读性、便捷性的提升 |
| 前置 | 生产已上线；本地为最新代码 |

---

## 1. 现状盘点（实测数据）

### 1.1 已经一致、无需大动

| 项 | 实测 | 结论 |
|---|---|---|
| 页面标题 | 36 个页面统一 `text-lg font-semibold text-gray-900` | ✅ 保持 |
| 表单标签 | 46 处统一 `text-xs font-medium text-gray-600` | ✅ 保持 |
| 容器卡片 | 统一 `rounded-xl border border-gray-200 bg-white`（p-4/p-5/p-8 按场景） | ✅ 保持 |
| 主色 | 蓝色为唯一主色（操作），灰阶为底 | ✅ 保持 |
| 横向溢出 | 抽查 6 个关键页均无横向溢出 | ✅ 保持 |

### 1.2 存在的不一致（按影响排序）

| # | 问题 | 实测证据 | 影响 |
|---|---|---|---|
| **B1** | **按钮尺寸有 6 种主样式 + 5 种次样式** | `bg-blue-600 px-4 py-1.5 text-sm` ×12、`px-2 py-1 text-xs` ×6、`px-5 py-2 text-sm` ×4、`px-4 py-2`、`px-3 py-1`… | 同类操作视觉不一，界面显得零散 |
| **B2** | **筛选交互两套并存** | 12 处需点「筛选」按钮；仅 2 处「选完即筛」 | 用户每次都要判断"我该点哪里" |
| B3 | 返回链接两种颜色 | 蓝色 5 处、灰色 6 处 | 同功能不同样式 |
| B4 | 空状态 39 处，写法零散 | 有的"暂无数据"、有的带引导 | 无数据时用户不知道下一步 |
| B5 | 术语混用 | 「供应商」与「厂家」并存（导航已改厂家，表单仍写供应商） | 概念混淆 |
| B6 | 间距节奏 | 容器 p-4 / p-5 / p-8 混用 | 页面呼吸感不均 |
| B7 | 提交后去向不一 | 部分提交后回列表、部分停留原页 | 操作预期不确定 |

### 1.3 工作链路抽查（6 个关键页）

| 链路 | 现状 | 卡点 |
|---|---|---|
| 开单（售卖/进货） | 客户/厂家 → 商品 → 数量价格 → 提交 | 已优化（卡片式、内联标签、提示齐全） ✅ |
| 查库存 | 列表 → 批次台账 → 当前库存对照 | ✅ 完整 |
| 收付款 | 应收应付列表 → 详情 → 登记 | ✅ 完整（登记入口在详情） |
| 单据操作 | 列表 → 详情 → 打印/退货/作废 | ✅ 完整 |
| 报表 | 报表中心 tab 切换 + Excel 导出 | ✅ 完整 |
| 基础资料 | 商品与厂家（含分类/单位/组织折叠区） | ✅ 完整 |

**结论**：**功能链路是完整的**，问题集中在 **① 视觉一致性（尤其按钮）② 交互一致性（尤其筛选）③ 空状态与引导** 三类"体验毛刺"，不是功能缺失。

## 2. 优化方案

### P0 — 建立规则并消除不一致（纯样式，零功能风险）

| # | 措施 | 具体做法 | 验证 |
|---|---|---|---|
| P0-1 | **按钮统一为 4 档** | 主：`h-9 px-4 text-sm 蓝底`；次：`h-9 px-4 text-sm 描边`；危险：`h-9 px-4 text-sm 红描边`；行内小按钮：`h-8 px-3 text-xs 描边`。全站替换（约 90 处） | grep 后仅剩 4 种尺寸 |
| P0-2 | **返回链接统一** | 详情页右上角用「次按钮」；表单页底部用统一的「← 返回列表」文字链 | 抽查 12 处 |
| P0-3 | **空状态统一组件** | 建 `EmptyState`：图标 + 主文案 + 可选引导按钮（"去创建商品"等），替换 39 处 | 组件唯一来源 |
| P0-4 | **危险操作统一** | 作废/删除：红描边按钮 + 二次确认文案；行内删除用低调文字按钮 | 抽查 |
| P0-5 | **间距节奏** | 页面级容器间距统一 `space-y-6`；卡片内 `p-5`；表格内边距 `px-4 py-2.5` | 抽查 |

### P1 — 交互一致性（把"要思考"变成"下意识"）

| # | 措施 | 具体做法 |
|---|---|---|
| P1-1 | **筛选统一交互** | 下拉/日期选择 → **选完即筛**（自动跳转）；文本输入（单号/关键词）→ **回车即筛**；保留「查询」按钮作为可见兜底。全站统一，不再混用 |
| P1-2 | **筛选条件跨页保留** | 分页/快捷时间/视图切换均保留全部筛选（已部分完成，补齐其余页面） |
| P1-3 | **提交后去向统一** | 新建/编辑表单 → 提交后回列表页并提示成功；单据操作（作废/退货/收付款）→ 停留在当前详情页并刷新 |
| P1-4 | **列表行加常用操作** | 单据列表行内直接提供「详情 / 登记」；库存行提供「批次」；商品行提供「编辑」——减少一次跳转 |

### P2 — 符合直觉

| # | 措施 | 具体做法 |
|---|---|---|
| P2-1 | **术语统一为「厂家」** | 表单/表格中「供应商」文案统一为「厂家」（数据库字段名不动，仅界面文案） |
| P2-2 | **空状态带引导** | 无数据时说明"为什么空 + 下一步做什么"，如"还没有商品，先去创建" |
| P2-3 | **页面标题区统一** | 所有页面统一为「标题 +（右侧）本页主操作按钮」，位置与样式一致 |
| P2-4 | **成功/失败反馈统一** | 所有写操作给出明确反馈（绿色成功 / 红色失败），位置统一在操作按钮旁 |

### P3 — 审美细节

| # | 措施 | 具体做法 |
|---|---|---|
| P3-1 | **颜色语义规范** | 红＝负向（未结清、负库存、亏损）；绿＝正向（已结清、盈利）；橙＝待处理（待收货、预警）；灰＝中性 |
| P3-2 | **表格密度与对齐** | 统一 `[&_td]:align-top [&_th]:whitespace-nowrap`（已部分完成），数字右对齐、文本左对齐 |
| P3-3 | **选中/悬停反馈** | 行悬停浅灰底、当前导航项高亮（已有），补齐列表行与卡片的悬停态 |

## 4. 不减少功能的保障

1. **改动前**：对涉及页面记录功能点清单（表单字段、按钮、跳转）
2. **改动中**：只调整样式类与交互方式，不改业务逻辑与字段
3. **改动后**：
   - 逐项核对功能点清单（勾选）
   - 关键链路实测（开单 / 收付款 / 退货 / 报表导出）
   - 桌面端截图前后对比
4. **数据层零改动**：本计划不涉及数据库结构与业务规则

## 6. 建议的执行方式

**分批小步提交**，每批（一个 P0/P1 小项）完成后：

1. 我提交并说明改了什么
2. 你在本地刷新查看
3. 有异议立即调整，再进入下一批

这样问题能在最小范围内被发现，避免一次性大改带来的回归风险。
